## Dane i usługi

- Mapa lokalizacji pobiera widoczne kafelki rastrowe bezpośrednio z `tile.openstreetmap.org`; projekt nie kopiuje ani nie dystrybuuje danych mapowych. Dane OpenStreetMap są udostępniane na ODbL, a panel pokazuje atrybucję „© OpenStreetMap contributors” z odnośnikiem do informacji o prawach autorskich. Publiczny serwer kafelków działa bez gwarancji dostępności i podlega osobnej [polityce używania kafelków](https://operations.osmfoundation.org/policies/tiles/): aplikacja pobiera tylko kafelki aktualnie wyświetlanego obszaru, korzysta z cache przeglądarki i nie udostępnia pobierania map offline. Nie należy traktować publicznego serwera jako usługi produkcyjnej z gwarantowanym SLA.
- Przykłady firmware w `examples/` są własnym kodem UltimateWX objętym GPL-3.0-or-later. Do zbudowania wymagają zewnętrznych bibliotek Arduino, których kodu projekt nie dołącza: Adafruit BME280 Library (BSD-3-Clause), Adafruit Unified Sensor (Apache-2.0), ArduinoMqttClient (LGPL-2.1). Zainstaluj je z Arduino Library Manager i zachowaj informacje licencyjne upstream przy dalszej dystrybucji firmware.

- Open-Meteo: odpowiedzi pogodowe na wolnym API podlegają CC BY 4.0, wymagają atrybucji; darmowa usługa API jest ograniczona do użytku niekomercyjnego. Sprawdź bieżące [warunki Open-Meteo](https://open-meteo.com/en/terms) przed wdrożeniem.
- IMGW-PIB: ostrzeżenia są pobierane z [publicznego API IMGW](https://danepubliczne.imgw.pl/apiinfo) (`warningsmeteo`). Wymagana atrybucja źródła danych: „Źródłem pochodzenia danych jest Instytut Meteorologii i Gospodarki Wodnej – Państwowy Instytut Badawczy”. Przed wdrożeniem należy sprawdzić aktualne warunki udostępniania danych IMGW.
- Deutscher Wetterdienst (DWD): aplikacja pobiera niemiecki status CAP z oficjalnego [publicznego kanału Atom](https://www.dwd.de/DWD/warnungen/cap-feed/de/atom.xml), wybiera alerty zawierające punkt stacji w geometrii CAP i zachowuje atrybucję `© Deutscher Wetterdienst (DWD)`. Warunki prawne DWD zaliczają publicznie dostępne informacje meteorologiczne i klimatyczne powiązane z lokalizacją do geodanych, które można ponownie wykorzystywać z podaniem źródła; CAP może dodatkowo wskazywać pole `LICENSE` dla użytych geodanych, wyświetlane przy alercie. Zobacz [warunki prawne DWD](https://www.dwd.de/EN/service/copyright/copyright_node.html) i [profil CAP DWD](https://www.dwd.de/DE/leistungen/opendata/help/warnungen/cap_dwd_profile_en_pdf_2_1_14.pdf?__blob=publicationFile&v=3).
- GeoSphere Austria: aplikacja pobiera ostrzeżenia dla gminy przez oficjalne [Warn API](https://openapi.hub.geosphere.at/warnapi/v1/). Data Hub podaje licencję CC BY 4.0; karty ostrzeżeń przypisują źródło GeoSphere Austria. Dane są pobierane dla współrzędnych stacji, bez pobierania geometrii administracyjnej. Zobacz [metadane usługi API](https://data.hub.geosphere.at/en/dataset/warnungen-v1/resource/warnungen-v1-api).
- MeteoAlarm/WIS2: aplikacja subskrybuje publiczny [strumień MQTT WIS2](https://api.meteoalarm.org/mqtt) na [oficjalnym brokerze WMO](https://community.wmo.int/site/knowledge-hub/programmes-and-initiatives/wmo-information-system-wis/wis-20-global-services). Dla każdego alertu adapter wymaga jawnych praw ponownego użycia i atrybucji w powiadomieniu, pobiera GeoJSON i dokument CAP po HTTPS oraz sprawdza prywatne adresy sieciowe. Objęcie stacji alertem potwierdza wyłącznie poligon z obszaru CAP; przybliżony bbox GeoJSON służy tylko do wczesnego odrzucenia, a alert bez poligonu jest pomijany. Adapter pomija CAP z niezgodnym parametrem `LICENSE`. Karty alertów podają atrybucję MeteoAlarm/EUMETNET i CC BY 4.0. Strumień jest bieżący, bez odtwarzania historii; zapisane alerty pozostają lokalnie do czasu wygaśnięcia, ale aplikacja nie może uzupełnić aktualizacji pominiętych podczas braku połączenia. Szczegóły [formatu powiadomień WIS2](https://wmo-im.github.io/wis2-notification-message/standard/wis2-notification-message-STABLE.html).
- GUGiK / PRG: dla automatycznego dopasowania polskiego powiatu do współrzędnych stacji aplikacja odpytuje usługę ULDK (GetCountyByXY). PRG jest udostępniany bezpłatnie i do dowolnego wykorzystania; [dokumentacja ULDK](https://uldk.gugik.gov.pl/opis.html), [informacje o PRG](https://www.geoportal.gov.pl/pl/dane/panstwowy-rejestr-granic-prg/). Przechowywany jest wyłącznie czterocyfrowy kod powiatu.
- PL-WARN/CAWF: UltimateWX nie kopiuje kodu projektu PL-WARN i nie publikuje przez ten kanał. Ewentualna integracja wymaga potwierdzenia pełnej specyfikacji CAWF oraz warunków użycia przed implementacją.
- Home Assistant, MQTT, APRS i czujniki użytkownika są źródłami konfigurowanymi lokalnie.

## TTS

- Piper TTS (`piper-tts`) jest instalowany jako osobny program z oficjalnego PyPI na Raspberry Pi OS/Debian i Ubuntu dla ARM64 oraz x86-64; nie jest łączony z binarium UltimateWX. Pakiet jest licencjonowany na GPL-3.0-or-later, więc może być używany w projekcie UltimateWX na GPL-3.0-or-later. Instalator przypina wersję 1.8.0. Wymagane pakiety Pythona są instalowane w oddzielnym środowisku w `/opt/ultimatewx/piper`; licencje głosów nadal trzeba sprawdzić dla każdego modelu osobno.
- Dla Raspberry Pi OS/Debian ARMv7 przygotowano eksperymentalny, osobny pakiet Piper 1.2.0 budowany w GitHub Actions dla `linux/arm/v7`. To starsza linia projektu Piper; jej repozytorium jest zarchiwizowane. Pakiet jest instalowany wyłącznie przez instalator systemowy na ARMv7 i nie jest częścią aktualizacji aplikacji. Każde wydanie z tym binarium zawiera `PIPER-ARMV7-SOURCES.tar.gz` z kodem Piper 1.2.0, Piper-phonemize 1.1.0, kodem eSpeak NG przypiętym do commitu `0f65aa301e0d6bae5e172cc74197d32a6182200f`, snapshotami źródeł ONNX Runtime 1.14.1 i spdlog 1.11.0 oraz użytymi plikami builda i upstreamowymi informacjami licencyjnymi. eSpeak NG jest na GPL-3.0-or-later; pozostałe komponenty zachowują własne licencje i noty. Sumy binarium, paczki źródeł oraz licencji znajdują się w `PIPER-ARMV7-SHA256SUMS`. Ten wariant jest eksperymentalny i wymaga testu wydajności na Raspberry Pi 2 B.
- Automatyczna instalacja pomija Alpine Linux (musl), bo pakiet ARMv7 jest budowany dla glibc, a oficjalne wydanie PyPI nie publikuje zgodnego koła dla Alpine.
- Katalog głosów pobiera model card, pokazuje tylko rozpoznane licencje z listy dopuszczonej w kodzie i przy instalacji sprawdza sumy kontrolne modelu oraz konfiguracji.
